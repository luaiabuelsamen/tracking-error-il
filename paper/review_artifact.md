# Anonymous review artifact

This artifact accompanies *Tracking Error as an Observation for Behavior
Cloning on Low-Cost Arms*. It contains source, frozen evaluation records,
analysis plans, and manuscript inputs. No network access, checkpoints, raw
training demonstrations, or physical robot is needed to rebuild the paper.

## Rebuild the evidence and manuscript

Use Python 3.10 or later with the versions in `requirements-paper.txt`.
System requirements are `make`, `latexmk`, a LaTeX installation including
Times fonts and `lineno`, and Poppler utilities (`pdftotext`, `pdfinfo`).

```bash
python -m pip install -r requirements-paper.txt
MPLCONFIGDIR=/tmp/tracking-error-matplotlib make paper
```

The final check recomputes trial counts, simulation contrasts, actual command
timing, and history-control status, and checks the reported numbers against
the saved evidence. The built `paper/main.pdf` remains anonymous. Cached
demonstration and checkpoint summaries support builds without raw inputs;
their status is explicit in `results/README.md`.

Tests of the analysis require `pytest`. The simulation tests additionally
require `mujoco` and the local package; hardware-pipeline tests use `torch`
and mock the robot. None of these tests command hardware.

```bash
python -m pip install -e '.[dev,analysis]'
make test
```

## Evidence and scope

- `results/hardware/`: original trial outcomes, trajectories, manifests,
  incident records, and training provenance. Missing outcomes stay missing.
- `results/simulation/`: every saved design-by-seed evaluation and additional
  unsuccessful screens. The primary comparison has no force threshold.
- `results/corpus/`: per-dataset effects and the frozen inputs to pooled
  statistics. The outcome is a kinematic retention proxy, not human labels.
- `docs/analysis_plans/`: dated historical simulation and corpus plans;
  `docs/hardware/`: hardware plans. The manuscript identifies later analyses.
- `paper/`: anonymous source, references, and generated quantitative tables.

The two completed hardware comparisons favor tracking error. Hardware
position-history control is incomplete after a servo/camera incident. New
versioned records are reported separately from the interrupted record.
Neither hardware force regulation nor broad training-seed reliability is
established. See the manuscript's protocol and limitations.

## Optional research assets

Separately prepared `demonstrations.zip` and `checkpoints.zip` use the same
top-level directory. Extracting them together supplies the original 50
demonstrations and the six evaluated plus two history-control checkpoints.
The large decoded image cache is omitted and regenerated by the training
loader. File hashes are recorded in each archive's `CONTENTS-<archive>.json`; hashes
of anonymized text metadata differ from historical source hashes by design.
The numerical trajectories and model weights are not altered.

Physical execution requires the author's bench setup, calibrations, and
supervised resets. It is not part of `make paper` or `make test`. Training
used platform-specific PyTorch builds and a patched LeRobot 0.3.4 source
tree; the version manifest and patch snapshot are under `results/hardware/`
and `scripts/bench/lerobot-patch/`. Hosted availability and the venue's
supplementary upload fields are not assumed by this artifact.

The `CONTENTS-*.json` manifests list each member's size and SHA-256 digest. Third-party
source attribution and license notices have been retained. Author metadata
has been removed from this copy for review.
